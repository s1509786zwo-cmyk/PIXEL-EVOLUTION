# 恒久データ保護ルール（最優先・全アップデート共通）

> **機能の追加よりも既存データの保護を優先する。**
> **データ保護の仕組みを確認できない状態では、既存データを書き換える作業を実行しない。**
> **データを守れないアップデートは実行しない。**

この文書は今回の修正だけのメモではなく、**今後 Arena.ai でコードや機能を変更するたびに適用される恒久ルール**です。新しいキャラクター・敵・武器・技・育成システム・ストーリー・画面・製作者ツールの追加、バグ修正、リファクタリング、設定変更のすべてに適用されます。

---

## 1. 変更のたびに必ず実行する（保護ゲート）

```bash
bash tests/verify_all.sh
```

- 最初に `tests/check_data_guard.mjs` を実行し、以下を **変更前 / 変更後 / ゲーム再起動後** の 3 点で検証します。
  - セーブが存在すること、キャラクター数が不自然に減っていないこと
  - 全キャラクターの固有 ID が変わらず残ること
  - 画像・名前・職業・ランク・レベル・ステータス・習得技・奥義・装備・育成が一致すること
  - 通貨・素材・アイテム・ガチャ履歴・ストーリー / ダンジョン進行・報酬受取履歴が一致すること
  - **今後追加される未知の項目**（名前を今は知らない将来のゲームデータ）まで残ること
  - 新機能を追加しても既存セーブが空データで上書きされないこと
  - 二重バックアップ・保存成功確認・保存失敗時の保護・読込失敗時の自動復元が動くこと
- 1 つでも失敗したら **その変更を適用せず、直前の正常な状態に戻す**。
  ```
  git diff --stat                              # 差分を確認
  git stash push -u -m 'revert-failed-change'  # または git restore <file>
  bash tests/verify_all.sh                     # 戻した状態で再度合格を確認
  ```
- 「テストを追加しただけ」「バックアップを作っただけ」では完了ではありません。

## 2. セーブデータの設計（additive-only / 新機能と既存データの分離）

| 原則 | 実装 |
| --- | --- |
| 新規ゲームの初期化は 1 箇所だけ | `js/state.js` の `newState()` のみ。`loadState()` が返すのは保存済みデータか `null` だけ |
| 既存プレイヤーの更新は 1 箇所だけ | `updateExistingSave()`。**`newState()` を呼ばない** |
| 既定値は「足りないキーだけ」補う | `fillMissing()` / `js/dataGuard.js` の `mergeAdditive()`。既存値を代入・削除・改名しない |
| 新しい画面を開く | 読み取り専用。`updateExistingSave()` は冪等で、開き直しても 1 項目も変わらない（テストで検証） |
| 新しいキャラクターを作成 | `createCharacter()` は配列に 1 人追加するだけ。既存 ID を再利用・変更しない |
| 既存項目の削除・改名・変更 | 必ず移行処理を用意し、旧値を新キーへコピーしてから旧キーを残す。移行前に自動バックアップ |
| 新機能に不具合があっても | `dataGuard` が保存前に破損を検知して書き込みを止め、以前の正常セーブを保持する |
| 将来追加されるデータ | **ホワイトリストを使わない**。`before` に存在するキーは未知でもすべて保護対象（`diffPreserved`） |

`js/dataGuard.js` は保存・UI に依存しない純関数です。

- `validateState(s)` — 形状・全キャラ ID の一意性・通貨 / コレクションの型を検査
- `diffPreserved(before, after)` / `assertPreserved` — 削除・値変更・配列縮小・ID 消失を検出
- `protectedFingerprint(s)` — 変更前後の同一性をハッシュで比較
- `assertNoLoss(before, next)` — 保存直前の消失検知（ゲーム進行による値の変化は許可）
- `mergeAdditive(s, defaults)` — 既存値を一切触らず、足りないキーだけ補う

`version / savedAt / lastDaily / quests / log` だけが日次更新を伴う可変項目です。それ以外は **すべて保護対象** です。

## 3. 二重バックアップと安全な保存（`saveState`）

```
破損検知(validateState)
  ↓
【保存前バックアップ】以前の原本をパースせずそのまま退避 (phase: before)
  ↓
書き込み：IndexedDB → 失敗時だけ localStorage（二重化）
  ↓
【保存成功確認】書き込んだ直後に読み直し、バイト列が一致するか照合
  ↓
存在証拠 (ocf_has_save) と世代・ハッシュ・ID 一覧をメタとして保存
  ↓
【保存成功後バックアップ】検証済み state を保存 (phase: after)
  ↓
saveReport() に成功・世代・バックアップ ID・消失検知を記録（設定画面に常時表示）
```

- 途中で失敗したら `failSave()` が **`saveGuard` を立てて以降の書き込みを停止** します。以前の正常なセーブデータは絶対に消しません。
- 保存前 / 保存後で `reason` と `phase` を分けているため、同一内容でも重複排除で片方が消えることはありません。
- `after` 世代だけが自動復元の候補です。隔離原本 (`quarantine`) や壊れたバックアップは候補にしません。
- `findLatestValidBackup()` は「本文を読む → JSON パース → `validateState` → 保存時ハッシュ照合」の 4 段を全部通した 1 件だけを返します。
- IndexedDB が健全な間は古い localStorage 本文を残しません（IDB 障害時に古いデータを読み込ませないため）。
- `tests/check_idb.mjs` が本来の保存先（IndexedDB）で成功確認・二重バックアップ・IDB 破損時の保護と自動復元を検証します。`tests/_harness.mjs` は IDB 未対応のフォールバック環境なので、両方の経路を必ずテストします。

---

## 4. 読み込み失敗時の絶対順序（`loadState` / `protectAndRecover`）

1. **現在のデータを保護** — 原本をパースせず隔離バックアップへ。`saveGuard = true` で上書き停止。
2. **エラー原因を記録** — `loadReport().errorDetail` と設定画面に表示。
3. **既存データを保持したまま再試行** — 書き込みは一切せず最大 3 回読み出し。検証に通った原本だけで復帰。
4. **バックアップを検証して復元** — 起動時 (`autoRecover:true`) は `after` 世代を検証して自動復元。
5. **復旧できなければエラーを表示して停止** — `null` を返し、設定画面へ。空の新規データで上書きしない。

> **「データが読み込めない」と「データが存在しない」を絶対に混同しない。**
> `ocf_has_save` フラグ / 保存メタ / IDB 読み取りエラーのいずれかがあれば「存在するはず」と判定し、保護手順へ進みます。本当に何も無い場合だけ新規ゲームとして扱います。
> IndexedDB が最初から無い環境は localStorage へ切り替えるだけの正常動作として区別します。

## 5. キャラクター ID と表示不具合の分離

- 全キャラクターに `uid()` による固有 ID。名前・配列 index では絶対に照合しません。
- 追加・編集・一括進化・削除は **対象 ID だけ** を操作します（`deleteChar` は単一 ID の filter）。
- 画像の読み込み失敗・表示バグは、**表示レイヤーのエラー表示だけ** で終わらせ、キャラクターデータを削除・変更しません。
- `validateState()` が ID の欠落・重複を保存前に検出します。

## 6. 新機能を追加するときのチェックリスト

- [ ] 新しい既定値は `defaultSaveFields()` に **追加** したか（既存キーを削除・改名していないか）
- [ ] `newState()` 以外の場所で初期化していないか
- [ ] 新しい画面は `state` を読み取るだけで、空オブジェクトを代入していないか
- [ ] 将来の未知キーを消すホワイトリスト / `Object.keys()` での作り直しを入れていないか
- [ ] 項目を改名する場合は旧値を新キーへ移す処理と移行前バックアップがあるか
- [ ] 画像・ID・技・装備の不一致時に「データを消す」分岐が入っていないか
- [ ] `bash tests/verify_all.sh` が **ALL SUITES PASSED** になったか
- [ ] 失敗した場合は変更を適用せず戻したか

---

## 7. 設定画面（🛡 データ保護レポート）

`設定・セーブ` に常時表示されます。

- 最終保存の成否・書き込み先・世代・キャラクター数
- 保存前 / 保存後バックアップの有無
- 消失検知（ID・保護項目）の警告
- 読み込み再試行回数・自動復元の有無と復元元 ID
- 保存エラー / 読み込みエラーの詳細と「原本は隔離済み、空データで上書きしていない」旨

保存が停止したまま復旧できないときは、下のバックアップ一覧から検証済みの `after` 世代を選んで **明示的に復元** します。勝手に新規開始へ進ませません。
